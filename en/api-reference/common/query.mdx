title: 'Query video task'
openapi: 'GET /v1/videos/{taskId}'
---

> Video URLs (`result.video_url`) are kept for about **3 days**. Download promptly.

Create and query share the same `data` shape. `data.cost` is the charged amount (credits).

For **Kling 4.0** (and similar per-second models with reference videos), query also returns a duration breakdown (seconds; upstream values preferred when present):

| Field | Description |
| :--- | :--- |
| `billable_seconds` | Actual charged video duration |
| `input_video_seconds` | Input video duration |
| `output_seconds` | Output / generated video duration (request `duration` until settled) |
| `reference_video_seconds` | Total reference video duration |

### Status values

| status | Meaning | progress |
| :--- | :--- | :--- |
| `queued` / `pending` / `submitted` | Submitted, waiting | `0` |
| `processing` / `in_progress` / `running` | Generating | `1–99` |
| `completed` / `success` / `succeeded` | Done — read `result.video_url` | `100` |
| `failed` | Failed — see `error_message` | `0` |
